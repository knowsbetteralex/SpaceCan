# AYM1 v1 — формат музыки SpaceCan для AY-3-8910/8913

**Статус:** спецификация v1, проигрыватель `ay_player.asm` (Step 16).
**Назначение:** конвертер на ПК формирует готовый поток записей в AY; Z80
только декодирует кадры. Самостоятельные MIDI-ноты в этом формате **не хранятся**.

## 1. Временная модель

- Один вызов `AY_TICK` соответствует одному слоту **1/50 с (20 мс)**.
- Состояние регистров сохраняется между записями. Никакой автоочистки
  голосов на каждом кадре нет: конвертер обязан выдавать выключение нот.
- Три тональных канала **A, B и C независимы**. Их одновременное звучание
  получается, когда все три канала имеют настроенные частоты и громкости.
- R6 (генератор шума) и R11–R13 (аппаратная огибающая) **общие** для чипа.
  В случае конфликтов решение принимается до сборки данных.
- Плеер рассчитан на заранее подготовленные записи **R0..R13**. GPIO
  **R14/R15 не трогает**. Биты 6 и 7 R7 принудительно обнуляются, то
  есть интерфейсные линии AY выставляются как входы.
- Целевая частота AY и частота кадров фиксируются **при конвертации**.
Исключение — встроенные тестовые треки `music.asm`, их периоды
пересчитывает сам ассемблер из `AY_TARGET_CLOCK`.
  Плеер не пересчитывает частоты или MIDI-tempo.

## 2. Заголовок (ровно 16 байт)

Все многобайтные целые числа — **little-endian**. Смещения от начала
конкретного музыкального блока (не от адреса загрузки).

| Смещение | Длина | Значение |
|---|---:|---|
| +0 | 4 | ASCII `AYM1` = `41 59 4D 31` |
| +4 | 1 | FPS: строго `50` |
| +5 | 1 | Флаги: бит 0 — loop; остальные должны быть 0 |
| +6 | 2 | Общий размер блока в байтах, **включая заголовок** |
| +8 | 2 | Смещение команды начала цикла, если loop=1; иначе 0 |
| +10 | 2 | Зарезервировано, строго `0` |
| +12 | 4 | Частота тактирования AY в Гц (например, 2000000) |
| +16 | ... | Поток команд |

Размер блока: от 17 до 65535 байт. Данные размещаются непрерывно;
ссылка на заголовок передаётся через `HL` в `AY_PLAY`. Блок не должен
пересекать границу адресного пространства Z80 `#FFFF`.

Текущий драйвер проверяет сигнатуру, FPS, флаги, размер, reserved
и допустимость смещения цикла. Поле частоты AY носит справочный
характер — перепроверять соответствие реальной плате обязан
конвертер/сборочный процесс. Полная проверка длины **каждой команды**
внутри декодера не делается: конвертер обязан выпускать корректный
поток, а не доверять сырым файлам без валидации.

## 3. Команды

| Первый байт | Полезная нагрузка | Эффект |
|---|---|---|
| `00` | Нет | END: остановка или переход в loop |
| `01..7F` | Нет | WAIT N: N кадров без новых записей |
| `80` | `mask_lo mask_hi [values...]` | FRAME: применить обновления регистров в **текущем** кадре |
| `81..FF` | — | Зарезервировано, v1 не допускает |

**FRAME** содержит 16-битную маску; разрешены только биты 0..13.
После маски идут байты значений регистров **по возрастанию номера**:
R0, R1, ..., R13 — только для установленных битов. Если задан бит 13,
R13 записывается **каждый раз**, даже если значение не изменилось;
это позволяет намеренно перезапустить аппаратную огибающую.

FRAME расходует **один** слот времени. WAIT N расходует N слотов.
Например, `FRAME, WAIT 2, FRAME` записывает первое состояние в кадре
0 и второе в кадре 3. Пустая FRAME (маска 0) допустима, но конвертер
должен заменить её на WAIT, если в этом нет особой необходимости.

Указатель loop обязан указывать **на границу команды** внутри потока,
не на `00` (END). На END при loop=1 курсор переносится и следующая
команда выполняется **в том же вызове AY_TICK**, без дополнительного
пустого кадра. Без loop=1 плеер вызывает `AY_STOP` и глушит звук.

Примеры:

```text
80 03 00 EF 00    FRAME: R0=239 (#EF), R1=0
02                WAIT 2 кадра
80 00 01 00       FRAME: R8=0, выключить голос A
00                END
```

У первого FRAME маска `0x0003`, у второго `0x0100`.
Одна команда FRAME не может содержать два обновления одного регистра;
если в музыкальном источнике они есть в одном слоте, конвертер
записывает **итоговое состояние** (кроме возможного события retrigger
R13, которое должно быть отражено наличием бита 13).

## 4. Регистры и аппаратные ограничения

| Регистр | Назначение | Разрешённые биты |
|---|---|---|
| R0,R2,R4 | Младший байт периода тона A/B/C | 0..7 |
| R1,R3,R5 | Старшие 4 бита периода тона | 0..3 |
| R6 | Общий период шума | 0..4 |
| R7 | Микшер: тон/шум A/B/C | 0..5, GPIO 6/7 всегда сбрасывать |
| R8,R9,R10 | Громкость (0..15) или бит 4 для hardware envelope | 0..4 |
| R11,R12 | Младший и старший байты периода огибающей | 0..7 |
| R13 | Форма аппаратной огибающей + retrigger | 0..3 |

Рекомендация для MIDI-конвертера: по умолчанию **software envelope** —
изменение громкости R8–R10 покадрово без аппаратной огибающей. Это
позволит независимо вести атаки/затухания перекрывающихся голосов.
Шум/аппаратная огибающая включаются только при согласованном
распределении общего ресурса.

Частота тона в Гц приблизительно равна
`AY_CLOCK_HZ / (16 * period)`. Например, при 2 МГц C5
(523,25 Гц) имеет период около 239; полный период занимает два
регистра (R0=239, R1=0). Допустимый период: 1..4095.

### Начальное состояние трека

**Первая команда должна быть FRAME**, задающая как минимум R0..R5,
R7 и R8..R10; при необходимости — R6, R11..R13. Плеер перед
каждым треком глушит чип и сбрасывает программное зеркало;
неустановленные регистры после старта имеют значения 0, R7=#3F.

Чтобы выключить завершившуюся ноту, конвертер должен выставить
амплитуду соответствующего канала в 0 и/или выключить тон в R7.

### Отдельные эффекты на бипере

Бипер остаётся на `#FE`. Записи AY `#FFFD/#BFFD` не используют
порты бипера и не смешиваются со спецэффектами внутри плеера.
Фактическое аппаратное смешивание AY и бипера зависит от аудиосхемы
конкретного Delta-C/внешней платы.

## 5. Точки интеграции с SpaceCan

- `AY_INIT`: один раз после старта.
- `AY_PLAY`: HL на новый поток; предыдущая песня прекращается.
- `AY_TICK`: один вызов на кадр только в обработчике IM2 (50 Гц), независимо от меню, игры или Game Over.
- `AY_PAUSE`: выключает звук и останавливает курсор/WAIT.
- `AY_RESUME`: восстанавливает R7 и R8–R10 из программного зеркала.
- `AY_STOP`: останавливает и глушит чип.

**Ограничение паузы:** аппаратная фаза envelope R11–R13 продолжает
течь на самом AY, даже когда логический счётчик кадров заморожен.
Плеер не перезапускает R13 при resume, чтобы не вызывать случайный
retrigger. Для безупречной покадровой паузы использовать программную
огибающую.

В `main.asm` параметр `AY_MUSIC_ENABLED EQU 1` включает
демонстрационные треки в меню/игре/концовке. Значение 0 возвращает
чисто биперный режим заставки и Game Over. На включении паузы
сохраняется биперная фраза ми–до–ми–доо.

## 6. Подключение результата конвертера

Вместо временных демонстрационных таблиц в `music.asm`:

```asm
AY_MUSIC_TITLE:
    INCBIN "assets/music/title.aym"
AY_MUSIC_GAME:
    INCBIN "assets/music/game.aym"
AY_MUSIC_GAME_OVER:
    INCBIN "assets/music/game_over.aym"
```

Каждый файл содержит **полный заголовок AYM1 и поток**, не только
payload. Не дублируйте заголовок ассемблерными директивами.
`AY_PLAY` получает **адрес начала файла**.

## 7. Проверки совместимости

1. Заголовок `AYM1`, FPS=50, размер, offset и clock верны.
2. Первая FRAME инициализирует все используемые каналы.
3. Все значения помещаются в регистры, маска не выходит за бит 13.
4. Звук R13 повторно запускается только когда бит 13 явно выставлен.
5. Все окончания нот имеют соответствующее выключение громкости.
6. При loop=1 цикл возвращается на границу команды без лишнего кадра.
7. При loop=0 END глушит звук и отключает player.
8. Файл не пересекает `#FFFF` в памяти Z80.
9. В игре каждый кадр проходит не более одного слота AY.
10. Взвешенное число событий после компрессии не превышает бюджет RAM.

Справочная документация по AY-3-8910/8913: даташит General
Instrument. Для ZX 128-совместимого портового интерфейса используются
`#FFFD` (выбор регистра) и `#BFFD` (запись данных). Для внешней
Delta-C-платы адреса и частоту обязательно проверить на железе.

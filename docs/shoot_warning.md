# SpaceCan — приоритетные предупреждения MOVE! и SHOOT!

## Логика

Один и тот же участок HUD (Y=2, X=13..18, 6 знакомест) выводит
**только одно** предупреждение. Во время обычного пролёта:

1. Если корабль не перемещался по горизонтали (реальный сдвиг
   на 4 пикселя влево/вправо) в течение **одной полной высоты**
   коридора (20 строк прокрутки), начинает мигать `MOVE!`.
2. Если корабль перемещается, но астероиды не уничтожаются в течение
   одного пролёта, появляется прежнее `SHOOT!` (счётчик по
   уничтоженным астероидам, не по нажатию SPACE).
3. Если выполнены **оба условия**, приоритет у `MOVE!`.
4. Через **три пролёта без движения** добавляется **одно красное
   штрафное деление**. Пока активно `MOVE!`, штрафы за
   отсутствие уничтожений не начисляются. Во избежание
   двойного штрафа счётчик отсутствия уничтожений обнуляется при
   MOVE-штрафе. При продолжительной неподвижности новый MOVE-штраф
   возможен через следующие три пролёта.
5. Через три пролёта без уничтожения астероида, если нет
   предупреждения `MOVE!`, начисляется прежний SHOOT-штраф.
   Уничтожение астероида обнуляет только SHOOT-таймер;
   горизонтальный сдвиг обнуляет только MOVE-таймер.
6. У штрафов **общий десятиделенный индикатор**: 10 красных
   делений снимают одну жизнь через стандартный взрыв.
7. Пауза и взрыв корабля не увеличивают счётчики; новая жизнь
   сбрасывает оба. На боссе MOVE/SHOOT не используются, остаётся
   индикатор выбранной атаки и шкала HP босса.
8. `0:MIX` остаётся основным режимом атак босса, настройки и
   тестовые режимы 1–6 сохраняются.

## Реализация

- `MISS_TRAVEL_ROWS` и `MOVE_TRAVEL_ROWS` независимы; единица —
  **строка движения мира**, а не 50-Гц кадр. Тем самым оба таймера
  автоматически следуют за текущей скоростью астероидов.
- `MOVE_CHANGED_THIS_TICK` выставляется **только** в ветке
  `.MOVED` после реального 4px перемещения, а не нажатия
  клавиши у границы. При сдвиге текущий шаг движения мира не
  учитывается для нового MOVE-интервала.
- `RENDER_SHOOT_WARNING` выбирает тип предупреждения и использует
  `SHOOT_VISIBLE` со значениями 0,1,2. `MOVE! ` занимает все
  6 знакомест, чтобы удалять остаток старого `SHOOT!`.
- Для скрытия используется прежнее
  `RESTORE_SHOOT_BACKGROUND`: восстанавливаются исходные 48 байт
  битмапа и 6 атрибутов без следов текста.

## Контрольные сценарии

- 19 строк без движения: MOVE! нет; 20 строк: MOVE! мигает.
- 60 строк без движения при попаданиях по астероидам: +1 деление;
  отсутствие стрельбы дополнительно не штрафуется.
- 20 строк с движением, но без уничтожений: SHOOT! мигает.
- 60 строк без уничтожений при регулярном движении: +1 деление.
- Корабль двинулся влево/вправо на 4 пикселя: MOVE! скрывается;
  SHOOT! может продолжить мигать.
- Удерживание O/P у границы не является перемещением.
- Пауза/потеря жизни обнуляют или замораживают таймеры правильно;
  оба предупреждения исчезают во время боя с боссом.

Тесты Python проверяют структуру и модель счётчиков. Сборка
sjasmplus в GitHub Actions проверяет синтаксис и границу памяти.
Игровое поведение и T-states нужно подтвердить в эмуляторе/на Delta-C.

# SpaceCan Step 17 — IM2 с AY на кадровом прерывании

## Почему не таблица с #FF00 и переходом на #FEFE

В IM2 CPU берёт вектор из двух байтов: низкий адрес =
`I*256 + byte_on_data_bus`. Для гарантированно полной таблицы
нужно **257 байт**, включая второй байт для случая `byte_on_data_bus=#FF`.

При `I=#FF` таблица `#FF00..#FFFF` заканчивается в `#FFFF`, а
последний старший байт будет считан из `#0000` (ПЗУ). Поэтому
предложенная комбинация **таблица от #FF00 → #FEFE** не является
безопасной для произвольного вектора шины данных.

Применена ближайшая безопасная компактная схема:

| Область | Назначение |
|---|---|
| `#FE00..#FF00` (257 байт) | Полная таблица из `#FD` |
| `#FDFD..#FDFF` (3 байта) | `JP IM2_HANDLER` |
| Регистр `I = #FE` | Адрес страницы таблицы |
| `SP = #FDFD` | Стек растёт вниз, не портит переход |
| `#FBFD..#FDFC` | Зарезервированные 512 байт стека |
| `#9000..` | Основная программа, проверка конца `PROGRAM_IMAGE_END` |

Вектор для любого байта `#00..#FF`: `#FD #FD` →
`#FDFD`. Вся таблица и переход формируются **при запуске
процедурой `IM2_INSTALL`**, поэтому в бинарник не добавляется
большой пробел `ORG #FE00`, не расходуется место на загрузочной ленте.
Компиляционный `ASSERT PROGRAM_IMAGE_END < IM2_STACK_GUARD`
должен запретить сборку, если программа залезает в стек или IM2.

## Порядок запуска и вызовы

```text
START (#9000):
    DI
    LD SP,#FDFD
    инициализация порта #FE / AY
    IM2_INSTALL     ; заполнить таблицу, записать JP, I=#FE, IM 2
    EI
    SHOW_START_MENU

IM2_HANDLER (раз в кадр, 50 Гц):
    сохранить AF/BC/DE/HL
    IM2_FRAME_COUNTER++
    AY_TICK         ; если AY_MUSIC_ENABLED=1
    восстановить AF/BC/DE/HL
    EI
    RETI

MAIN_LOOP:
    HALT
    RENDER_FRAME → RENDER_HUD → KEY_POLL/UPDATE_GAME → SFX_TICK
```

`AY_TICK` **больше не вызывается** из меню, Game Over или
обычной игровой логики: единственное место — обработчик IM2.
Это сохраняет темп даже если графический кадр занял больше обычного.
Если обработчик оказался длиннее одного кадрового интервала, CPU
не сможет воспроизвести пропущенные кадры: мониторить нагрузку
по-прежнему необходимо.

После потери жизни `RESTART_ROUND` больше не запрещает
прерывания на всю перерисовку экрана: AY продолжает играть.
На паузе `AY_PAUSE` глушит чип, но IM2 продолжает исполняться;
`AY_TICK` не продвигает данные при `AY_PAUSED=1`.
Биперный сигнал паузы и биперная мелодия перед AY-заставкой
сохраняются.

## Критические секции и регистры

- Публичные процедуры управления AY (`AY_PLAY`, `AY_STOP`,
  `AY_PAUSE`, `AY_RESUME`) сохраняют начальное IFF2 через
  `LD A,I`/флаги, временно выполняются с `DI` и восстанавливают
  состояние прерываний. Это защищает и программное зеркало регистров,
  и двухшаговые `#FFFD/#BFFD` операции записи.
- ISR вызывает внутренний `AY_STOP_RAW` **без `EI`**, когда
  композиция завершилась или поток некорректен.
- Обработчик сохраняет AF, BC, DE, HL. Текущие `AY_TICK` и
  `AY_WRITE_REG` не меняют IX/IY/альтернативные банки; если это
  изменится, расширить сохранение регистров.
- `SFX_TICK` на бипере остаётся в основном цикле. Короткие серии
  импульсов защищены `DI…EI` (без IRQ посередине включённого EAR),
  чтобы обработчик IM2 не создал щелчков или растянутых полуволн.
  Это даёт небольшую задержку AY на время пакета SFX.
- ROM IM1 больше не обслуживает клавиатуру/системный `FRAMES`.
  SpaceCan использует прямое чтение порта клавиатуры и собственные
  счётчики; системные возможности ROM, которым нужен IM1, нельзя
  использовать без отдельного адаптера.

## Проверки перед релизом

1. Выполнить sjasmplus сборку `main.asm` и
   `space_step17_standalone.asm`; проверить `ASSERT` и фактический
   адрес `PROGRAM_IMAGE_END`.
2. В отладчике проверить `#FE00..#FF00 = FD`,
   `#FDFD = C3` и `(#FDFE) = IM2_HANDLER`.
3. Убедиться, что вход в программу по `#9000` начинается
   с `DI`/`LD SP`, а `HALT` возвращает управление каждый кадр.
4. Проверить AY при меню, игре, Game Over; при паузе не меняется
   счётчик музыкальных кадров. После снятия паузы музыка продолжается.
5. Биперное вступление слышно **до** AY; SFX ударов/взрывов не
   дёргает border и не создаёт длинных залипаний EAR.
6. Проверить сборку `AY_MUSIC_ENABLED=0`: **без любых AY портов**,
   но с IM2 и работающим бипером.
7. На модифицированной Delta-C (INT в начале кадра) сравнить
   длительность и стабильность звука на обычном и загруженном кадре.

**Статус:** исходники и структурные проверки готовы; машинная
сборка sjasmplus/тест на железе пока не выполнены.

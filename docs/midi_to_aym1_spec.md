# Техническое задание: MIDI → AYM1 конвертер для SpaceCan

**Статус:** ТЗ v1, конвертер пишется **как отдельный инструмент на ПК**.
**Результат:** проверенный готовый `.aym` для прямого `INCBIN` в ZX
Spectrum 48K. Логика анализа MIDI, распределения голосов и компрессии
**не переносится на Z80**.

Основная спецификация бинарного формата: [aym1_format.md](aym1_format.md).

## 1. Интерфейс инструмента

Рекомендуемый язык — Python 3, библиотека для Standard MIDI File
например `mido`, собственная модель AY-регистров и энкодер AYM1.

Пример CLI (планируемый, **пока не реализован**):

```sh
python midi2aym.py input.mid -o output.aym \
  --clock 2000000 --fps 50 --loop auto \
  --voices 3 --overflow steal --percussion noise \
  --instrument-map instruments.json --report output.json
```

Настройки: MIDI источник, целевая частота AY (пресет 2 МГц
для Delta-C, отдельный стандартный 1,7734 МГц), FPS=50,
режим loop, приоритеты дорожек/каналов, громкость, mapping
инструментов, обработка барабанов, правила потери голосов,
начало/конец композиции, параметры сжатия и отчёт.

Файлы на выходе:
- `track.aym` — полный AYM1 (включая 16-байтовый заголовок);
- `track.report.json` — длительность, использование 3 каналов,
  число потерянных/украденных нот, предупреждения, размер;
- по опции `track.frames.csv` — 14 регистров на каждый кадр для
  отладки и сравнения эмулятора;
- по опции короткий WAV-прослушиватель, полученный **эмуляцией AY**
  (не синтезом MIDI SoundFont), чтобы оценить компромиссы.

## 2. Входные данные MIDI

- Поддержать SMF format 0 и 1, несколько треков и MIDI-каналов.
- События `note_on` с velocity=0 эквивалентны `note_off`.
- Обработать `set_tempo` и смены темпа, абсолютное время переводить
  через единую tempo map из MIDI ticks в секунды.
- Поддержать velocity, program change, control change (как минимум
  CC7 volume, CC10 pan как опциональную политику, CC11 expression,
  CC64 sustain, CC120 all sound off, CC123 all notes off).
- Поддержать pitch bend (по умолчанию ±2 полутона, RPN sensitivity
  на следующем этапе). Период AY пересчитывать каждый кадр.
- Drum channel 10 (MIDI channel index 9) распознавать отдельно.
- MIDI Type 2 и SMPTE time division на первом этапе отклонять
  понятным сообщением; не интерпретировать время неправильно.
- Системные Exclusive/мета-данные сохранять в отчёте при необходимости;
  неподдерживаемые команды пропускать с предупреждением.

## 3. Критично: перекрывающиеся ноты и аккорды

Нельзя обрабатывать MIDI как один поток `NOTE_ON → NOTE_OFF`,
перетирая текущую ноту при следующем `NOTE_ON`.

Для каждого события хранить минимум:
`note_id, midi_channel, source_track, pitch, velocity, start,
key_release_time, actual_end_time, sustain_state, priority`.

- Новый `note_on` **не выключает** ранее зажатые ноты.
- При `note_off` выключается только соответствующий экземпляр
  ноты. Если тот же pitch был запущен дважды до первых Note Off,
  хранить очередь активных экземпляров и использовать **FIFO**
  по ключу (MIDI-канал, высота) как детерминированное поведение
  по умолчанию. Фиксировать эту неоднозначность в отчёте.
- Если CC64 (sustain) удерживается, `note_off` снимает состояние
  клавиши, но **не прекращает звук** до отпускания педали или
  команды all sound off.
- Накладывающиеся release-хвосты учитываются как звучащие голоса,
  даже после события `note_off`.
- Длительность ноты формируется после MIDI note-off по огибающей
  инструмента, но в пределах доступной трёхголосной полифонии.
- События в одном времени обрабатываются детерминированно: сначала
  release/sustain-off, затем новые атаки; внутри исходного MIDI
  сохраняется стабильный порядок по исходному track/event index.

### Распределение по каналам AY

AY имеет только **три независимых генератора тона** (A/B/C).
При числе одновременных звучащих MIDI нот ≤3 конвертер должен
сохранять все три без потери и без превращения аккорда в арпеджио.

На каждом кадре:
1. Вычислить набор звучащих MIDI-голосов с учётом sustain, release
   и текущей амплитуды.
2. По возможности удерживать прежнее сопоставление
   `note_id → AY A/B/C`, чтобы избежать дребезга и лишних записей.
3. Для новых нот выбирать свободный AY-канал, учитывая назначенный
   приоритет дорожки, канал и вес инструмента.
4. При 4+ голосах применять явную стратегию переполнения:
   **`steal` по умолчанию** (украсть самый тихий/самый низкоприоритетный
   или находящийся в release), **`drop`** или
   **`arpeggiate`** (опциональное чередование нот в пределах кадров).
5. Каждое принудительное отключение/возобновление логировать
   (потерянные ноты, время, трек, причина).
6. При исчезновении голоса явно записать R8/R9/R10=0 (либо
   отключить соответствующие биты микшера) — иначе AY продолжит
   звучание старой ноты.

**Пример при перекрытии:** MIDI C4 начинается в t=0, E4 в t=0.10,
G4 в t=0.20. С t=0.20 до завершения C4 все три ноты должны
звучать **одновременно**. Если при t=0.30 начинается B4 — четыре
MIDI-ноты физически не поместятся в три AY-канала; конвертер
обязан применить указанную стратегию, а не молча потерять первую.

## 4. Инструменты, динамика, шум и огибающие

- Velocity 1..127 → нелинейная кривая громкости AY 0..15 с
  поддержкой CC7/CC11 и пользовательской нормализации; на каждом
  кадре рассчитывать огибающую канала (attack/decay/sustain/release).
- Preset инструмента определяет тональную волну, громкость,
  длительности ADSR, вибрато/арпеджио, допустимый шум, приоритет.
- **По умолчанию все три голоса используют software volume**
  через R8–R10. Это позволяет независимо отпускать аккордовые ноты.
- R6 (шум) **общий** для всех каналов, а R11–R13 описывают **одну**
  аппаратную огибающую. Конфликтующие запросы от разных инструментов
  нельзя безоговорочно писать одновременно. Начальный профиль:
  использовать software envelopes, R13 вообще не писать.
- Опциональный профиль аппаратной огибающей: один назначенный
  «владелец» в каждый момент, явные R11/R12 и retrigger R13.
  Каждая даже повторная запись R13 значима.
- Перкуссию MIDI channel 10 в MVP маппить на короткие шумовые
  события AY с политикой `noise` и занятием одного из трёх каналов,
  либо отключать `--percussion off`. Нельзя предполагать четвёртый
  независимый шумовой голос — шумом управляет тот же микшер.
- Стереопанорама MIDI сама по себе не реализуется на моно-AY:
  CC10 можно использовать лишь для выбора A/B/C при известной
  схеме разведения каналов платы либо игнорировать с предупреждением.

## 5. Высота звука, частота AY и время

Целевая высота `midi_note`:

```text
freq_hz = 440 * 2 ** ((midi_note + bend_semitones - 69) / 12)
period  = round(ay_clock_hz / (16 * freq_hz))
period  = clamp(period, 1, 4095)
```

Конвертер записывает младшие/старшие разряды period в R0/R1,
R2/R3 либо R4/R5. Отдельно учитывать разные целевые частоты
реальной AY-платы Delta-C (номинальный пресет **2 МГц**) и
стандартных 128K (**~1,7734 МГц**); пересчёт только на ПК.

**BPM в MIDI:** учитывать всю tempo map, а не одно исходное BPM.
Сначала переводить события в абсолютные секунды, после чего
квантовать **на общую сетку 50 Гц**. Не округлять каждый интервал
по отдельности, иначе накопится дрейф.

```text
frame_index = round(absolute_seconds * 50)
```

Для события нулевой длительности и для нескольких атак в одном
кадре определить порядок и report; невозможно воспроизвести
отдельные атаки, не умещающиеся в 20 мс, без subframe-драйвера.
Первый этап — строго 50 кадров/с, без прерываний 100/200 Гц.

## 6. Формирование кадров и сжатие AYM1

Пайплайн:

```text
SMF MIDI
  → объединённая временная шкала / tempo map
  → note instances + CC64 + release tails
  → 3-voice scheduler + per-voice volume/pitch/noise
  → 14 регистров (R0..R13) на каждые 20 мс
  → маски изменившихся регистров / важные retrigger R13
  → FRAME / WAIT 1..127 / END (+ loop header)
  → бинарный файл AYM1 + JSON отчёт
```

Требования к энкодеру:
- Первая FRAME инициализирует **как минимум R0..R5, R7..R10**,
  а R6/R11..R13, когда они используются.
- Не записывать неизменённые регистры, кроме R13 при re-trigger.
- Не трогать R14/R15, сбрасывать биты 6/7 R7.
- FRAME кодируется `80 maskLo maskHi values...`; порядок значений
  всегда R0..R13. Биты 14/15 mask строго 0.
- WAIT N = N полных кадров без новых регистров; разрезать периоды
  более 127 кадров на несколько WAIT.
- END = `00`; при циклическом треке loop offset указывает на начало
  команды и не должен создавать пустого кадра.
- Выровнять положение цикла с музыкальной фразой либо loop markers,
  по умолчанию loop на начало payload. Флаг loop=0 — однократный трек.
- Заголовок заполнять строго по `AYM1 v1`. Общий размер ≤65535;
  при превышении автоматически выдавать ошибку/предлагать разбить
  композицию на сегменты, **не** создавать неправильный файл.
- 32-битное поле clock — только метаданные; Z80-плеер его не меняет.

## 7. Проверка результата и измеримые критерии

### Тесты времени и полифонии

1. Один `C4` длительностью 1 с даёт правильный period и не менее
   50 временных слотов до окончательного выключения.
2. Аккорд C4/E4/G4 на 1 секунду звучит на A/B/C одновременно; все
   три амплитуды ненулевые на совместных кадрах.
3. C4 начинается раньше E4, которая начинается раньше G4; отпускание
   C4 не прерывает E4/G4.
4. Повторный note_on C4 до note_off C4 обрабатывается по FIFO,
   без преждевременного выключения второго экземпляра.
5. CC64 удерживает ноты до отпускания педали.
6. Четвёртая нота на том же участке вызывает строго заявленный
   steal/drop/arpeggiate; отчёт содержит конкретную потерю.
7. Изменение темпа MIDI на середине файла даёт правильную
   длительность в кадрах без накопленного дрейфа.
8. Барабанный удар обрабатывается как noise/scheduled voice,
   не нарушая громкости чужого AY-канала.
9. При повторной записи R13 энкодер не выбрасывает команду как
   «неизменённый регистр».
10. `END` и loop без зависаний, остановка приводит к тишине.

### Валидация бинарника

- Сопоставить бинарник с эталонным Python-декодером: после развёртки
  FRAME/WAIT на каждый кадр должны получиться одинаковые R0..R13.
- Проверить корректность длины, FPS, смещения цикла, порядка значений
  маски, допустимых диапазонов регистров, отсутствие чтения за EOF.
- По возможности сравнить эмуляцию AYM1 и напрямую рассчитанных
  кадров (частоты, динамика, приоритеты и огибающая).
- Отчёт должен указывать среднюю/пиковую полифонию, число
  украденных нот и кадров, где превышен лимит трёх голосов.
- Тестовый мини-MIDI: короткие наложения, аккорд, sustain, изменение
  BPM, program change, pitchbend, 4+ голосов, барабан и loop.
- Проверить скомпилированный Z80 на Spectrum 48K + Delta-C AY:
  музыка не останавливает биперные спецэффекты, удерживает темп,
  правильно приглушается/возвращается после паузы.

## 8. Этапы реализации внешнего конвертера

1. **MVP:** SMF 0/1, tempo map, note on/off, 3 tone voices,
   software volume, steal/drop, 50 Гц, AYM1, отчёт, валидация.
2. **Контроллеры и выразительность:** sustain, pitchbend,
   program/instrument mapping, ADSR, громкостные кривые.
3. **Продвинутые эффекты:** шумовая перкуссия, shared envelope,
   вибрато/арпеджио, управление loop markers, оптимизация потока.
4. **Качество:** визуализация занятости каналов, предпрослушивание
   через эмулятор AY, автоматические регрессионные тесты.

**Не цель:** воспроизводить MIDI-полифонию без ограничений,
использовать SoundFont на Z80 или разбирать `.mid` на Spectrum.
Преобразование может быть приближением оригинала из-за лимитов AY;
все потери должны быть явными и управляемыми.
